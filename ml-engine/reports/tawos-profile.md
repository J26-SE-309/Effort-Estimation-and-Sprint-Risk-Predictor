## 2. How sprint membership is stored

- Issues with at least one change to the Sprint field: **71,376**; issues that were ever in two or more sprints: **34,970**.
- Each change stores the *whole* list of sprints (e.g. `103` then `103, 106`), so the full membership history can be rebuilt from `Change_Log`.
- `Issue.Sprint_ID` is set for 43,475 issues; 9,645 of them have no Sprint history in `Change_Log`.
- For the 34,970 multi-sprint issues, `Issue.Sprint_ID` is empty for 54.9%. When it is set, it is a sprint from the issue's final list (99.6% of those), consistent with the TAWOS description of it as the sprint the issue was delivered in; it matches the first sprint in 54.5% and the most recently added one in 33.5%. **It cannot be used on its own for spillover or carry-over labels (R1, R2, R5); membership must come from the `Change_Log` history.**
- `Sprint.JiraID` is not unique: 4,594 sprint rows, 2,565 distinct Jira IDs, 4,178 distinct (repository, Jira ID) pairs; 273 pairs appear in more than one project (a sprint shared by several projects is stored once per project). Sprint IDs from `Change_Log` must be resolved per repository and project.
